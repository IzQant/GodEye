# 프론트엔드 UI/UX 개선 기록

작성일: 2026-08-30 (6주 로드맵 종료 후, 확장 착수 전 UI 정비)
대상: app/templates/index.html (단일 파일, Jinja2 + 커스텀 CSS/JS)

## 디자인 테마
- 다크 테마, 배경 단색 #020715 (그라데이션 없음).
- 포인트 컬러: #FFC349(주) / #EB7D00(보조). 버튼·토글은 단색 #FFC349
  (그라데이션 제거). 제목만 세로 그라데이션(#FFC349→#EB7D00) 유지.
- 모든 요소 각진 사각형(border-radius 0).
- 제목 GodEye: 픽셀 폰트 Press Start 2P(Google Fonts), 크게(2.85rem), 중앙 정렬.
  제목 옆 점 장식 제거.
- matchId/이미지 탭 위 파란 포인트 바 제거.
- 맵 선택란과 단계 입력란 높이·모양 통일(44px, select 커스텀 화살표).

## 화면 흐름 (3단계 스크린, 아래로 쌓지 않음)
제목(GodEye)은 모든 화면 상단에 항상 표시. 한 번에 한 화면만 보임.
1. 입력 + 지도 영역 지정
   - matchId 탭 / 이미지+단계 탭.
   - 이미지 선택 시 같은 화면에 "지도 영역 지정" 캔버스 표시(4클릭 또는 자동감지).
     사진 보정을 기본 흐름에 통합(체크박스 삭제). 꽉 찬 스크린샷은 지정 없이 예측 가능.
2. 현재 원 직접 표시 (자동 검출 실패 시에만 전환)
   - 드래그로 현재 원 지정 → "표시한 원으로 예측" / "뒤로".
3. 예측 결과
   - 결과 카드: 맵 / 단계 / 불확실성 반경(단위 m). 좌표·상태 항목은 제거(간결화).
   - 원 예측 ↔ 히트맵 세그먼트 토글(둘 다 미리 로드 → 즉시 전환). 각 뷰 범례 표시.
   - 하단 "처음으로" 버튼 → 입력 화면으로 복귀 + 상태 초기화.

## 구현 메모
- 폼 <form> submit 대신 JS로 FormData를 직접 조립(buildFD): 화면이 나뉘어도
  image/phase/map/corners/manual 좌표를 하나로 모아 /api/analyze·visualize·heatmap에 전송.
- currentBuilder('match'|'image')로 경로 구분. matchId는 보정/수동 단계 없이 바로 결과.
- 히트맵 토글 없이도 결과에서 원/히트맵 전환(예전 체크박스 방식 폐기).
- 범례 색은 백엔드가 실제 그리는 색과 일치(현재=흰, 예측=파랑, 불확실성=청록, 히트맵 그라데이션).

## 반영된 사용자 피드백 요약
- 사진은 보통 모니터 밖까지 찍힘 → 보정을 기본 단계로 승격.
- 히트맵 버튼이 작고 구석 → 결과 내 토글로 승격.
- 아래로 쌓이는 방식 불편 → 3화면 분리 + "처음으로".
- 결과의 좌표/상태 불필요 → 제거, 불확실성에 m 단위.
- 버튼 그라데이션 → 단색 #FFC349.

- 화면 전환 애니메이션, 반응형(모바일) 미세조정, 로딩 상태 시각 강화.
