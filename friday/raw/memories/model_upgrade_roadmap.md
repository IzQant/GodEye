## 1. RF vs MLP — 대량 데이터(예: 10,000매치) 시 정확도

- 신경망(MLP)은 데이터가 늘수록 성능 상한이 높다. 지금 56매치에서 MLP가
  꼴찌였던 건 과적합 때문이지 방법이 나빠서가 아니다.
- 그러나 우리 데이터는 정형(tabular, 특징 소수)이라, 이런 경우 트리 앙상블이
  데이터가 많아도 신경망과 대등하거나 더 나은 경우가 흔하다.
- 결론:
  - 가장 기대값 높은 선택은 **Gradient Boosting(LightGBM/XGBoost)**.
    정형 대량 학습에서 RF·MLP를 모두 이기는 경우가 흔하고 배포도 가볍다.
  - RF vs MLP 둘 중에서는, 특징 설계+튜닝을 제대로 하면 대량 데이터에서 MLP가
    근소 우위 가능. 튜닝 없이 키우면 RF가 더 안정적.
  - 배포 관점: RF(joblib)는 가볍고 단순, MLP(torch)는 이미지가 무거움 →
    1인·무료 배포에선 RF/트리 계열이 유리.
- 더 근본적 지렛대: 문제를 **시계열로 재구성(LSTM 등)**. 자기장은 이전 단계
  흐름에 의존하므로 단발 예측보다 궤적 기반 예측이 크게 나아질 수 있음.
  (로드맵 확장 Phase 7에 이미 포함)

## 2. 맵별 모델 분리

- 자기장 당김 패턴은 맵마다 달라, 데이터가 충분하면 맵별 분리가 정확도에 도움.
- 그러나 지금(56매치)은 맵별 표본이 부족(Vikendi 7, Paramo 7, Rondo 6 등)해서
  분리하면 오히려 악화. 지금은 **단일 모델 + 맵 원-핫 특징**이 최선(공유 학습 이점).
- 권장 경로:
  1) 현재: 단일 모델 + 맵 특징 유지.
  2) 서빙 계층(model_service.py)을 "맵을 키로 모델 조회, 없으면 전역 모델 폴백"
     구조로 설계 → 나중에 코드 대공사 없이 맵별 모델 삽입 가능.
  3) 전환 기준: **맵당 약 100~150매치 이상** 모이면 그 맵만 전용 모델로 승격,
     그 이하 맵은 계속 전역 모델 사용 (하이브리드).
- 10,000매치 시나리오에서는 주요 맵 대부분이 기준을 넘으므로
  맵별 분리 + (LightGBM 또는 LSTM)이 정석이 됨.

## 3. 적용 순서 (요약)
1. 지금: RF(delta) 단일 모델로 배포까지 (현 로드맵 유지).
2. 배포 안정화 후: 데이터 대량 수집.
3. 맵별 매치 수가 임계치 넘으면: 맵별 하이브리드 모델 + LightGBM 검토.
4. 흥미/여유 시: LSTM 시계열 모델(로드맵 Phase 7)로 다단계 예측 확장.
