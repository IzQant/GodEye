# 발표자료 개요 (GodEye — PUBG 자기장 예측)

Week 5 정리 시점 초안. 발표/포트폴리오용 구성.

## 1. 문제 정의
- PUBG에서 다음 자기장(안전지대)이 어디로 좁혀질지 예측하고 싶다.
- 입력: matchId(텔레메트리) 또는 전체 지도 스크린샷 + 현재 단계.
- 출력: 다음 원의 위치·반경 + 불확실성, 지도 위 시각화.

## 2. 접근 (파이프라인)
- 데이터: PUBG Open API 텔레메트리 → 단계별 자기장 좌표 데이터셋(CSV).
- 예측: 단계 전환(phase N→N+1) 회귀 모델(RandomForest) + 단계별 축소비율/불확실성.
- 검출(선택): 스크린샷에서 원 검출(OpenCV HSV+Contour), 실패 시 수동 지정.
- 서빙: FastAPI + Jinja2 웹 UI, /api/analyze 통합 엔드포인트, 지도 오버레이.

## 3. 시스템 구조
- 텔레메트리 수집·파싱 → 데이터셋 → 모델 학습(joblib) → FastAPI 서빙
- 이미지 경로: 업로드(+사진 보정 4모서리) → 검출/수동 → 좌표변환 → 예측 → 오버레이
- PostgreSQL(요청 로그), slowapi(레이트리밋), Docker 배포(Week 6)

## 4. 핵심 의사결정 & 배운 점 (정직하게)
- 초반 목표(같은 스냅샷 safety→poison)는 near-identity라 무의미 → 단계 전환으로 재구성.
- 자기장 중심은 무작위성이 커 '중심 정확 예측'은 원리적 한계 → 가치는 '반경 축소 + 불확실성'.
- 실제 스크린샷 색상 검출은 배경 간섭으로 불안정 → 수동 클릭/드래그 + 사진 보정으로 보완.
- 데이터/생성물은 git에 넣지 않고 스크립트로 재생성(대용량 push 사고에서 배움).

## 5. 결과
- 단계 전환 예측 오차(중심, m): copy 159 / baseline 160 / RF 167 (중심은 어렵다는 증거).
- 반경 축소 예측은 단계별 패턴(0.57~0.73)을 잘 재현, 불확실성 범위 제시.
- 로컬 웹 데모: matchId/이미지 두 경로 모두 예측+지도 오버레이 시연 가능.

## 6. 한계와 향후
- 데이터 규모(수십~백 매치)로 후반 단계 표본 부족.
- 검출 자동화는 딥러닝(YOLO 등, 확장 Phase 6) 필요.
- 중심 예측 개선은 지형/시계열(LSTM, 확장 Phase 7) 여지.

## 7. 데모 시나리오 (발표용)
1) matchId 입력 → 예측 + 오버레이.
2) 전체지도 스크린샷 + phase + (사진 보정) → 검출/수동 → 예측 + 오버레이.
3) 잡음/실패 입력 → 수동 좌표 지정 폴백 시연.
