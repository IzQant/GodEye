# 특징점 매칭 자동 지도 정렬 (서비스 적용 기록)

작성일: 2026-08-31
배경: 모바일에서 꼭짓점 4탭·드래그 입력이 어려움 → 촬영 사진에서 지도 영역을
'자동 추출'하는 방법 10가지 검토 후, 특징점 매칭(1번)을 채택·구현.

## 구현
- app/services/map_align.py
  - 참조 맵(data/maps/<map>.png, 1024 정사각)과 사진의 SIFT 특징점을 BF-KNN 매칭
    (Lowe ratio 0.75) → RANSAC 호모그래피(사진→지도 좌표계).
  - 참조 맵 특징점은 1회 계산 후 캐시. 사진은 최대 1600px로 축소해 매칭(속도),
    H는 스케일 보정해 원본 픽셀 기준으로 반환.
  - 성공 판정: good>=30, inliers>=25, inlier비율>=0.25. 실패 시 (None, None, info).
- app/routers/analyze.py: _decode_and_warp(map_name 추가)
  - corners(수동 4점) 있으면 기존 수동 보정.
  - 없으면 자동 정렬 시도 → 성공 시 사진이 전체지도 정사각으로 보정되고
    manual 원좌표도 H로 함께 변환. 실패 시 원본 유지(기존 폴백 그대로).
  - analyze / visualize / heatmap 세 엔드포인트 모두 적용.
- 프론트: 영역 지정 힌트를 "선택사항 — 자동 인식 우선(권장)"으로 변경.
  수동 4점은 자동 인식이 어긋날 때의 폴백으로 유지.

## 검증 (합성 '촬영 사진': 에란겔을 원근 왜곡 + 어두운 배경 + 노이즈)
- 정렬: 매칭 2,278 / 인라이어 2,270. 지도 꼭짓점 복원 오차 최대 0.1px.
- 엔드투엔드(/api/analyze, corners 없이): 자동 정렬 → 원 검출 → 맵 좌표 변환 성공.
  현재 원 중심 오차 0.6m (정답 대비). 예측 정상 생성.
- 기존 테스트 회귀 없음.

## 의미
- 모바일 사용자: 꼭짓점 탭 없이 사진만 올리면 됨(핵심 UX 문제 해소).
- 검증은 합성 사진 기준. 실제 폰 촬영(모아레·반사·저조도)에서 인라이어가
  줄 수 있으므로 실사진 테스트 필요. 실패 시 수동 4점/원 지정 폴백은 그대로 동작.
- 주의: 게임 UI(자기장 원·마커)가 지도 위에 그려져 있어도 SIFT 매칭은
  나머지 지형 특징점으로 정렬 가능(부분 가림 강건성 확인됨).

## 실사진 검증 결과 (2026-08-31 추가)
- 사용자 테스트에서 결과가 원본 사진 배경으로 출력 → 정렬 실패가 '조용히' 폴백된 것 확인.
- 실측(사용자의 실제 태이고 촬영 사진):
  - 443px 사진: good 5 → 실패. (개선 후 good 36/inlier 10 — 여전히 기준 미달, 정직한 거부)
  - 1376px 사진: good 115 / inlier 93 → 성공. 오버레이 원이 그려진 사진도 정렬됨.
  - 결론: 실패 주원인 = 사진 해상도(다운스케일 업로드). 참조 맵도 447px로 저해상.
- 개선 적용:
  1) 참조 맵을 원본 해상도로 매칭(업스케일 보간 뭉갬 제거), H는 출력 크기로 후환산.
  2) 재시도 사다리: 기본 → CLAHE → (900px 미만이면) 2x 업스케일+CLAHE.
  3) 침묵 폴백 제거: AnalyzeResponse에 aligned(bool|null) 추가,
     프론트에서 aligned=false면 경고 표시("고해상도 원본 사용 또는 4점 지정").
- 흐름 확인: 큰 실사진 → aligned=True + (색상 검출은 실패라 needs_manual) →
  사용자가 수동 원을 그리면 H로 변환되어 정확한 맵 좌표가 됨. 의도된 동작.

## 남은 것 / 권장

- data/maps/ 참조 맵을 1024px+ 고해상도로 교체하면 매칭이 더 강해짐(권장).
