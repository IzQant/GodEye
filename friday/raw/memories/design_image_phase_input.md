# 설계 결정: 이미지 업로드 + phase 입력 예측 (Week 5 구현 목표)

작성일: 2026-08-17 (Week 4 종료 시점 확정)
상태: 확정 — Week 5(Day 29~31)에서 이 구조로 구현.

## 핵심 아이디어
사용자가 게임의 '전체 지도 화면(M 키)'을 촬영해 업로드하고, 현재 phase와 맵을
직접 입력하면 다음 자기장을 예측한다. 이미지 경로의 'phase를 알 수 없는' 문제를
사용자 입력으로 해결하고, CV는 '현재 원 위치 찾기'에만 집중한다.

## 왜 이 방식인가
- 미니맵/스크린샷만으로는 현재 phase를 자동 검출하기 어렵다(단계 숫자가 화면에 없음).
  phase는 사용자가 확실히 알고 입력이 쉬움 → 가장 약한 고리를 사람이 메움.
- matchId 경로의 제약(PUBG API 필요, 최근 14일만)에 안 묶임. 스크린샷만 있으면 됨.
- Day 25에서 만든 '수동 입력 폴백'의 자연스러운 확장.

## 필수 전제
- 반드시 '전체 지도 화면'을 업로드해야 함(미니맵 구석 창 X).
  전체 지도는 프레이밍이 고정 → 픽셀→맵(cm) 변환이 이미지크기·맵크기만으로 성립
  (make_map_overlays와 동일 가정). 임의 크롭/확대 미니맵은 매번 보정 필요해 불안정.

## 처리 흐름
업로드 이미지 + phase + map
  → CircleDetector로 현재 흰 원(safety) 픽셀 중심/반경 검출
  → coordinate_transform(전체맵 스케일)로 맵 좌표(cm) 변환
  → ZonePredictor.predict(safety_x, y, radius, phase, map)
  → 다음 원 중심/반경/신뢰구간
  → 업로드 이미지 위에 현재/예측 원 오버레이(PNG) 반환

## 견고성 규칙
- phase: 항상 사용자 입력(신뢰).
- map: 사용자 선택(드롭다운).
- 현재 원 위치: 자동 검출 우선 → 신뢰도 낮거나 실패 시 사용자가 원 중심/반경을
  직접 입력(수동 폴백). needs_manual 플래그로 UI 분기.

## 구현 시 바뀌는 부분 (Week 5)
1. 스키마: analyze 요청에 phase, map 필드 추가. (이미지 경로용)
2. /api/analyze(Day 30): 이미지+phase+map → 위 흐름. matchId 경로는 기존대로.
3. 프론트엔드(Day 31): 이미지 업로드 + phase 입력 + 맵 선택 + '전체 지도 업로드' 안내,
   검출 실패 시 수동 좌표 입력 UI.
4. 좌표 변환: 전체맵 스케일(coordinate_transform.full_map_affine) 사용.

## 정직한 한계
- 실제 스크린샷의 흰 원 HSV 검출은 튜닝 필요. 안 되면 수동 폴백으로 완결.
- 전체맵 좌표축(y 방향)이 게임과 반대면 FLIP 처리 필요(오버레이 때 확인).
